# TerraCORE IDE — Prototype

Block Code → MicroPython สำหรับ ESP32 พร้อมสลับโหมดระหว่าง **Block** กับ **โค้ด MicroPython**
เก็บโปรเจกต์ทั้งหมดไว้ใน SQLite

ขอบเขตของ prototype ตัวนี้คือช่วง `Block UI → MicroPython Generator` ตาม MVP Checklist ในสไลด์
ยังไม่รวม Web Flasher, Device Simulator, Dashboard และ AI Copilot

## รัน

```bash
python3 app.py
```

เปิด http://127.0.0.1:5001 — ฐานข้อมูล `terracore.db` ถูกสร้างให้อัตโนมัติครั้งแรกที่รัน

ไม่ต้องต่อเน็ต: Blockly ถูก vendor ไว้ใน `static/vendor/blockly/` แล้ว (รวมภาษาไทย)

ไม่ต้องต่อเน็ต: Blockly และฟอนต์ถูก vendor ไว้ในโปรเจกต์แล้ว

## Deploy prototype

มีชุด Docker + Kubernetes + Argo CD สำหรับ deploy ผ่าน Cloudflare Tunnel ที่
`https://terracore.denmannsolutions.com` แล้ว อ่านขั้นตอนตั้งแต่ build image, ตั้ง Argo CD,
เพิ่ม Published application route จนถึง rollback/backup ได้ที่
[deploy/README.md](deploy/README.md)

ถ้า Argo CD ติดตั้งอยู่ใน namespace `argocd` แล้ว deploy ได้ทันทีด้วย:

```bash
kubectl apply -f https://raw.githubusercontent.com/TxngJr/TerraCorePrototype/main/deploy/argocd/application.yaml
```

## หน้าตา

ธีมสว่าง เส้นคั่นบางเป็นตัวแบ่งหลัก เงาใช้เฉพาะชั้นที่ลอยจริง (เมนู/กล่องยืนยัน)
สีถูกสงวนไว้ให้บล็อกกับโค้ด ส่วน chrome เป็นหมึกกับเทา — ม่วงทำหน้าที่เดียวคือ
บอกโหมดที่เลือกอยู่กับตำแหน่ง focus

- ไม่ใช้อิโมจิเลยทั้งในบล็อกและหน้าเว็บ บล็อกอาศัยข้อความไทยกับสีประจำหมวด
  ส่วนปุ่มที่ไม่มีข้อความใช้ SVG เส้นบาง
- renderer ของ Blockly ใช้ `geras` (กระชับ เหลี่ยมกว่า) แทน `zelos` แบบ Scratch
  ให้เห็นโค้ดต่อหน้าจอได้มากขึ้นและเข้ากับ thesis "ไปถึง Production ได้จริง"
- ตัวอักษรตั้งไว้ให้อ่านออกตอนฉายโปรเจกเตอร์ (UI 14px, โค้ด 14px)
  คอนทราสต์ทุกคู่สีผ่าน WCAG AA
- รองรับเดสก์ทอปกับแท็บเล็ตแนวนอน (กว้าง ≥768px) จอแคบกว่านั้นแสดงหน้าแนะนำ
  ให้ไปเปิดบนจอใหญ่ เพราะการลากบล็อกบนมือถือใช้งานจริงไม่ไหว

## สองโหมด

| | Block Code | MicroPython |
|---|---|---|
| แก้ไข | ลากบล็อก | พิมพ์โค้ดตรง ๆ |
| โค้ด | สร้างใหม่ทุกครั้งที่บล็อกเปลี่ยน | ผู้ใช้แก้เองได้ |

พอแก้โค้ดด้วยมือ โปรเจกต์จะถูกทำเครื่องหมาย `code_dirty` และขึ้นป้าย
"⚠ แก้ด้วยมือ — ไม่ซิงก์กับบล็อกแล้ว" การกลับไปโหมด Block จะถามยืนยันก่อน
เพราะโค้ดที่แก้เองจะถูกเขียนทับด้วยโค้ดที่สร้างจากบล็อก
(เป็นทางเดียวเหมือน MakeCode — ยังไม่มีการแปลงโค้ดกลับเป็นบล็อก)

## บล็อกที่มี

- **เริ่มต้น** — เมื่อเริ่มทำงาน, ทำซ้ำตลอดไป, หน่วงเวลา
- **เอาต์พุต** — ตั้งขาดิจิทัล, สลับสถานะ, PWM, แสดงข้อความ
- **อินพุต / เซนเซอร์** — อ่านดิจิทัล, อ่านอนาล็อก, ปุ่ม, DHT11/DHT22, แปลงช่วงค่า
- **WiFi & Cloud** — เชื่อมต่อ WiFi, เช็คสถานะ, ส่งค่าขึ้น TerraCORE Cloud
- และหมวดมาตรฐานของ Blockly (ตรรกะ, วนซ้ำ, คณิตศาสตร์, ข้อความ, ตัวแปร, ฟังก์ชัน)

### ชื่อตัวแปรภาษาไทย

Blockly จะแปลงอักษรที่ไม่ใช่ ASCII เป็นรหัสฐานสิบหก (`อุณหภูมิ` → `_E0_B8_AD_...`)
ซึ่งอ่านไม่รู้เรื่องและ MicroPython บนบอร์ดจริงก็ไม่รับ
ตัวแปลงจึงถอดเสียงเป็นอักษรโรมันให้แทน (`อุณหภูมิ` → `ounhphumi`) แล้วแนบตารางเทียบไว้ในโค้ด
การถอดเสียงเป็นแบบประมาณ ขอแค่อ่านออกและได้ผลเหมือนเดิมทุกครั้ง ไม่ได้ยึดตามหลัก
ราชบัณฑิตยสภาแบบเป๊ะ ๆ

## Copilot (ต้นแบบ — ยังไม่ใช้ AI จริง)

ระบบแนะนำบล็อกถัดไป เป็น **กฎ if/else** ล้วน ๆ ยังไม่มีโมเดลภาษาอยู่เบื้องหลัง
ข้อเสนอจะขึ้นเป็นบล็อกจาง ๆ ขลิบเส้นประ ต่ออยู่ตรงตำแหน่งจริงที่มันจะไปอยู่
กด "วางบล็อก" แล้วจึงกลายเป็นบล็อกจริง กด "ไม่ใช่ตอนนี้" แล้วกฎนั้นจะเงียบไป
จนกว่าจะเปลี่ยนโปรเจกต์

กฎเรียงตามความรุนแรง ตัวที่ทำให้โปรแกรมพังมาก่อน:

| กฎ | เงื่อนไข | เหตุผล |
|---|---|---|
| `empty-start` | พื้นที่ทำงานว่าง | ชวนเริ่มจากไฟกะพริบ |
| `wifi-before-cloud` | มีบล็อกส่ง Cloud แต่ไม่มีบล็อกต่อ WiFi | ไม่ต่อก่อนข้อมูลส่งไม่ออก |
| `map-analog-to-pwm` | ต่อขาอนาล็อกเข้า PWM ตรง ๆ | 0–4095 ยัดใส่ช่อง 0–1023 ไฟสว่างสุดค้าง |
| `loop-needs-delay` | ลูปไม่มีหน่วงเวลา | บอร์ดวนจนกินซีพียูเต็มและอาจค้าง |
| `finish-the-blink` | สั่งเปิดไฟแต่ไม่มีสั่งปิด | ไฟติดค้าง ไม่กะพริบ |
| `send-sensor-to-cloud` | อ่านเซนเซอร์แล้วแต่ไม่ได้ส่งไปไหน | ต่อยอดเป็น Dashboard |
| `print-sensor-value` | ไม่มีการแสดงค่าออก Serial | ไว้ตรวจว่าเซนเซอร์อ่านได้จริง |

ข้อเสนอมีสองชนิด:

- **เพิ่มบล็อก** (`connect` / `top`) — ต่อบล็อกใหม่เข้าไปในตำแหน่งที่ควรอยู่
- **ครอบ/แก้สาย** (`wrap`) — ถอดบล็อกเดิมของผู้ใช้ออกมาแล้วยัดเข้าไปในบล็อกที่ครอบ
  เช่นเอา "อ่านค่าอนาล็อก" ไปไว้ในบล็อกแปลงช่วงค่าก่อนส่งให้ PWM
  ตอนกด "ไม่ใช่ตอนนี้" จะคืนสายกลับให้เหมือนเดิมทุกประการ

ลองดูได้จากตัวอย่าง **"หรี่ไฟตามแสง (ต่อผิด)"** ในเมนูโปรเจกต์

บล็อกที่เป็นข้อเสนอถูก `setEnabled(false)` ไว้ ตัวแปลงโค้ดของ Blockly จึงข้ามมันเอง
และระหว่างมีข้อเสนอค้างอยู่ หน้าโค้ดจะ **หยุดนิ่งไว้ที่โค้ดของโปรแกรมจริง**
ไม่สร้างใหม่ (เพราะข้อเสนอชนิดครอบย้ายบล็อกจริงไปอยู่ในตัวครอบชั่วคราว)
autosave ก็ไม่เขียนลงฐานข้อมูลจนกว่าจะกดยืนยัน

การแตะ workspace ของ Copilot ทุกครั้งถูกห่อด้วย `Blockly.Events.disable()` —
ถ้าปล่อยให้ event ยิงออกมา ฝั่งแอปจะนึกว่าผู้ใช้แก้บล็อกแล้วสั่งเก็บข้อเสนอทิ้ง
จากนั้นตั้งเวลาเสนอใหม่ กลายเป็นวนกระพริบทุก ๆ 0.9 วินาที

## ผังการต่อวงจร (mockup)

ปุ่ม **"ดูการต่อวงจร"** บนหัวพื้นที่บล็อก เปิดโมดัลที่วาดบอร์ด **ESP32 DevKit v1 (30 ขา)**
พร้อมขาครบทุกขา แล้ว**กระพริบเฉพาะขาที่โปรแกรมนี้ใช้** ข้าง ๆ เป็นคำอธิบายว่าแต่ละขา
ต้องต่ออุปกรณ์อะไร ใช้ตัวต้านทานค่าเท่าไร ลง GND ตรงไหน

- ถ้าเลือกบล็อกไว้ก่อนกด ขาของบล็อกนั้นจะถูกตีกรอบเข้มและเด้งขึ้นบนสุดของรายการ
- GPIO 2 กับ GPIO 0 ไม่ได้อยู่บนแถวขาของบอร์ดจริง — เป็น **LED บนบอร์ด** กับ **ปุ่ม BOOT**
  จึงวาดเป็นอุปกรณ์บนแผ่นวงจรและบอกว่าไม่ต้องต่อสายเพิ่ม
- บล็อกที่ยังเป็นข้อเสนอของ Copilot (`setEnabled(false)`) จะไม่ถูกนับ

ความรู้เรื่องการต่ออยู่ใน `GUIDE` ของ [wiring.js](static/js/wiring.js) เป็นข้อความที่เขียนไว้
ล่วงหน้าต่อชนิดบล็อก **ยังไม่ได้วิเคราะห์วงจรจริง** และยังไม่เตือนกรณีใช้ขาซ้ำซ้อนกัน

## API

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/projects` | รายการโปรเจกต์ |
| POST | `/api/projects` | สร้างใหม่ |
| GET | `/api/projects/<id>` | อ่านโปรเจกต์ (พร้อม workspace + code) |
| PUT | `/api/projects/<id>` | บันทึก (ส่ง `snapshot: true` เพื่อเก็บเวอร์ชัน) |
| DELETE | `/api/projects/<id>` | ลบ (revisions ถูกลบตาม) |
| GET | `/api/projects/<id>/revisions` | รายการเวอร์ชัน |
| GET | `/api/revisions/<id>` | อ่านเวอร์ชันย้อนหลัง |

autosave ทำงานหลังหยุดแก้ 0.8 วินาที และจะข้ามถ้าเนื้อหาไม่ได้เปลี่ยนจริง
ปุ่ม 💾 บันทึก (หรือ ⌘/Ctrl+S) จะเก็บ revision ไว้ด้วย เก็บสูงสุด 30 เวอร์ชันต่อโปรเจกต์

## ตรวจงานแบบ headless

```bash
node tools/gen_examples.js /tmp/gen
```

สร้างไฟล์ `.py` จากตัวอย่างทั้ง 4 ชุดโดยไม่ต้องเปิดเบราว์เซอร์ ใช้ตรวจว่าโค้ดยัง compile ผ่าน
หลังแก้ตัวแปลง (ทั้ง 4 ชุดผ่าน `py_compile` แล้ว)

```bash
npm test
```

ยิงกฎของ Copilot ใส่ workspace จำลอง 7 แบบ แล้วเช็คว่ากฎที่ควรทำงานคือตัวไหน
รวมถึงเคสที่ไม่ควรเสนออะไรเลย (ผ่านครบ 7 เคส)

## ที่ยังไม่ได้ทำ

- แปลงโค้ดกลับเป็นบล็อก (โหมดโค้ดเป็นทางเดียว)
- Copilot ยังเป็นกฎ if/else ไม่ใช่ AI — ยังไม่รู้จักโจทย์ที่นักเรียนตั้งใจทำ
  ได้แต่ดูว่าโครงบล็อกขาดหรือผิดตรงไหนตามรูปแบบที่เขียนกฎไว้ล่วงหน้า
- ยังแก้ "ค่าในช่อง" ของบล็อกเดิมไม่ได้ (เช่นบอกว่า DHT22 ต้องเว้นอย่างน้อย 2 วินาที
  แล้วขอแก้เลข 500 เป็น 2000 ให้) ทำได้แค่เพิ่มบล็อกกับครอบบล็อก
- ผังการต่อวงจรยังไม่เตือนเมื่อใช้ขาซ้ำกันคนละหน้าที่ และไม่มีรายการอุปกรณ์รวม (BOM)
- Web Flasher / Device Simulator / Dashboard
- ระบบผู้ใช้ — ตอนนี้ทุกคนที่เปิดเห็นโปรเจกต์ชุดเดียวกัน ยังไม่มี Class Code หรือ Teacher Dashboard
- `cloud_send()` ยิงไปที่ URL สมมติ (`api.terracore.dev`) ยังไม่มี endpoint จริงรองรับ
